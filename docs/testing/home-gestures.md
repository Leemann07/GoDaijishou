# 홈 제스처 수정 검증

기준: PR #7 (`8faa7be`)을 포함한 `fix/home-gesture-reliability` 브랜치.

## 확인한 코드 경로

- 기존 슬림 바는 `mHandleWidth`, `mHandleMaxWidth`, `mHandleHeight`, `mRadius`,
  `mFullgestureNavHeight`를 변경했고, 그리는 동안 `mDy`도 바꿨다. 일부 값은 그린 뒤에도
  남았다. 수정본은 캔버스만 축소·이동하고 LG의 필드는 읽기만 한다.
- 기존 폴백에서는 소유자가 아닌 감시자의 UP이 소유권을 지울 수 있었다. 완료 직후
  늦게 도착한 동일 DOWN도 새 제스처로 등록될 수 있었다. 수정본은 소유자·다운 시각·입력
  장치를 확인하고 완료·취소 후에도 마지막 다운 시각을 보존한다.
- 기존 릴리스 속도는 마지막 MOVE와 UP 두 좌표만 사용했다. 수정본은 Android의
  `VelocityTracker`를 사용한다. 최근 앱은 거리 임계점 통과 시간 대신 실제 정지 시간을 본다.
- 시작 영역은 화면 하단 10% 대신 24dp와 시스템 필수 제스처 인셋을 기준으로 한다.
  화면 크기는 DOWN에서 실제 디스플레이를 조회하고 회전·크기가 바뀐 상태에서 UP이 오면 취소한다.
- 서드파티 홈에서도 홈·최근 앱 키를 전달한다. 런처 자체 설정 화면이나 드로어를
  홈으로 잘못 판정해 홈 키를 막던 패키지 기반 억제는 제거했다. LG 기본 홈은 기존 처리에 맡긴다.
- 실제 제스처 모드·잠금 해제·화면 켜짐·확정된 서드파티 홈일 때만 폴백을 켠다.
  시작과 종료에 다시 조회하며, 런처 변경이나 새 터치 뒤 늦어진 이전 판정은 실행하지 않는다.
- 마우스·펜·다중 터치·취소 플래그가 있는 입력을 배제한다. NaN/무한대 좌표와
  역순 시각도 판정기 자체에서 차단한다. 상태 조회 실패는 폴백 비활성화로 처리한다.
- HOME/최근 앱 DOWN·UP은 같은 누름 시각과 명시적인 display 0으로 주입한다.
  DOWN 실패/예외에도 UP을 시도하며 주입 허용 여부를 로그로 남긴다.

이 변경 전후의 기기 비교가 없어 **슬림 옵션이 실제 증상의 원인이었다고 확정하지 않는다.**
키보드 여백 옵션이 SystemUI 프레임 높이를 줄이던 전역 리소스 훅은 제거했다.
키보드 내부 버튼 줄 제거는 유지하지만, 시스템 바의 높이·입력 영역은 순정으로 남긴다.
따라서 기기에 따라 종전보다 키보드 아래 여백이 남을 수 있으며 실기기 확인이 필요하다.

## 자동 검증

JDK 17과 Android SDK 34 환경에서:

```sh
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:assembleRelease
```

`HomeGestureTrackerTest`: 감시자 중복·지연 이벤트·취소 후 재시도·입력 장치 구분·하단 앱 스크롤·
빠른 스와이프·정지 유지·천천히 계속 이동·되끌기·가로 스와이프·가로 화면 좌표를 검증한다.
이는 입력 상태 판정의 JVM 테스트이며 LG 시스템의 실제 실행이나 캔버스 표시를 검증하지 않는다.

이번 작업 환경에서 35개 테스트 및 디버그·릴리스 빌드 통과.
중복·지연·취소·역순 입력 20,000건의 결정적 무작위 시퀀스에서 동일 제스처의 중복 실행도 검사한다.
전체 `lintDebug`는 실패했다. 같은 환경에서 PR 원본도 실행해 비교한 결과 오류가
66개에서 64개로 줄었고 새 오류는 없었다. 기존 권한·최소 API 관련 오류는 별도 작업으로 남는다.

## 적대적 재검수

수정 전 판정기에 반례 4개를 추가해 모두 실패함을 확인한 뒤 보강했다.
상위 입력 어댑터의 소유권 검사에만 의존하던 상태도 판정기 안에서 직접 보호한다.

| 반례/위험 경로 | 조치 | 검증 범위 |
| --- | --- | --- |
| 완료 후 같은 UP 재호출 | 활성 소유권을 검사하고 한 번만 결과 반환 | JVM 회귀 테스트 |
| 취소 후 늦은 UP | 취소한 스트림은 다시 완료할 수 없음 | JVM 회귀 테스트 |
| NaN/무한대 좌표·속도 | 스트림 취소, 실행하지 않음 | JVM 회귀 테스트 |
| 오래된 MOVE가 정지 시간을 과거로 되돌림 | 마지막 이벤트보다 이전인 시각 무시 | JVM 회귀 테스트 |
| 다른 감시자·입력 장치의 MOVE/UP/CANCEL | 판정기 내부에서 소유자·다운 시각·장치를 대조 | JVM 회귀·무작위 테스트 |
| 3버튼·잠금·화면 꺼짐·불명 상태 | 보완 동작 비활성화 | JVM 정책 테스트, 실제 서비스 조회는 기기 검증 필요 |
| 키보드 옵션이 SystemUI 바의 크기 변경 | 전역 프레임 리소스 훅 제거 | 소스 검토, 실제 여백·제스처는 기기 검증 필요 |
| 잘못된 키 누름 시각·포커스 디스플레이 | 동일한 DOWN 시각과 display 0을 명시, UP 보장 시도 | 소스 검토·컴파일, 실제 주입은 기기 검증 필요 |

릴리스 CI에서도 `:app:testDebugUnitTest`가 통과해야 APK 빌드·발행 단계로 진행한다.

## 실기기 검증 (미실행)

ADB 연결 기기가 없어 아래 항목은 아직 확인하지 못했다. 훅 코드가 바뀌므로 설치 후 재부팅한다.

LG 기본 홈과 실제 사용하는 서드파티 홈 각각에서 아래 4가지 조합을 확인한다.
키보드 여백 설정을 바꿀 때는 시스템 UI와 키보드 재시작이 필요하므로 재부팅 후 비교한다.

| 슬림 바 | 키보드 여백 줄이기 | 상태 |
| --- | --- | --- |
| 끔 | 끔 | 미확인 |
| 켬 | 끔 | 미확인 |
| 끔 | 켬 | 미확인 |
| 켬 | 켬 | 미확인 |

각 조합의 세로·가로 화면에서:

- [ ] 앱의 하단 가장자리에서 빠르게 올려 홈으로 이동, 연속 20회.
- [ ] 앱에서 올려 멈춘 뒤 손을 떼면 최근 앱, 10회. 서드파티 홈 위에서도 확인.
- [ ] 천천히 계속 올리면 홈, 올렸다 아래로 되끌면 취소.
- [ ] 가장자리보다 위에서 시작하는 앱 스크롤과 가로 이동은 홈으로 전환되지 않음.
- [ ] 두 손가락·시스템 CANCEL 뒤 다음 한 손가락 제스처가 정상 동작.
- [ ] 키보드를 띄운 앱과 전체화면 앱에서도 홈·최근 앱 정상 동작.
- [ ] 제스처 도중 회전·화면 전환은 잘못된 홈 전환을 만들지 않음. 다음 제스처 정상 동작.
- [ ] 잠금 해제 제스처를 홈으로 처리하지 않음. 슬립·깨우기·재부팅 후 반복 확인.
- [ ] 메인/세컨드 화면 전환 후 각 화면의 원래 홈·뒤로·최근 앱 동작 확인.
- [ ] 옵션 토글 후 막대의 두께·폭·위치·색·상승 표시가 정상이며 다른 화면 표시가 변하지 않음.
- [ ] 3버튼 모드에서 하단 앱 스크롤이 홈·최근 앱으로 처리되지 않음.
- [ ] 런처 선택 대화상자·기본 홈 변경 중에도 중복 전환이나 잘못된 최근 앱 실행이 없음.

필요한 로그:

```sh
adb logcat -s GoDaijishouGesture:V '*:S'
```

로그의 `inject HOME/RECENTS accepted=true`는 시스템이 DOWN·UP 주입을 받아들였다는 뜻이다.
실제 화면 전환 성공은
눈으로 확인하거나 `dumpsys activity activities`로 별도 확인한다.

## 2.1.3 재진단과 실기기 결과 (2026-11-16, LG Wing A13)

2.1.1~2.1.2의 "LG 홈이 아니면 제스처가 끝나지 않는다"는 전제는 틀렸다. LG quickstep은 기본 홈이
Nova·Daijishou여도 `FallbackSwipeHandler`와 `RecentsActivity`로 홈·최근 앱을 직접 처리한다.
폴백이 같은 스와이프에 HOME 키를 추가로 주입해 quickstep 애니메이션 도중 두 번째 이동이 일어났다
(로그: `finishTouchTracking ... FallbackSwipeHandler` 직후 `fire HOME`, uid 0의 HOME 시작).

- 폴백은 SystemUI `OverviewProxyService.mOverviewProxy`가 null일 때(quickstep 미연결)만 동작한다.
  상태를 읽지 못하면 꺼진다. 런처 재시작 직후 1~2초는 연결은 됐지만 quickstep이 준비 전이라
  어느 쪽도 처리하지 않는다(순정과 같음).
- 잠금 중 터치가 먹지 않던 원인: 화면이 꺼진 뒤 LG AOD 안내(`com.lge.displayfingerprint`)가
  `wakeUpForExtendedDisplay`로 부분 깨움을 요청하고, 스위블이 열린 상태라 세컨드 화면이
  잠금화면을 띄운 채 켜지지만 시스템은 비대화형이라 터치가 버려졌다. 메인 화면 모드에서는
  `PowerManagerServiceEx.partialWakeUpNoUpdateLocked`가 false를 반환한다(LG의 폴더 닫힘·주머니 차단과 같은 경로).
- 세로 화면에 가로 최근 앱 카드: quickstep이 다른 패널 기준 DeviceProfile을 유지했다.
  메인 디스플레이 패널(짧은 변·긴 변·dpi)이 바뀌면 `InvariantDeviceProfile.onConfigChanged`를 호출하고,
  제스처 DOWN에서도 한 번 더 비교한다.
- 2.1.2에서 뺀 키보드 프레임 높이 훅은 원인이 아니었으므로 복원했다.

adb 합성 입력으로 확인: Nova·Daijishou 빠른 스와이프 = 홈, 천천히 멈춤 = 최근 앱, 폴백 주입 0건,
잠금·해제 3회 후 카드 세로(648x792), 부분 깨움 차단 로그, 내비게이션 프레임 38px.
미확인: 실제 손가락, ES-DE·Pegasus, 세컨드 화면 모드.
